# 旅の余白

`npm run dev:fast` で起動し、`/trip-planner` を開きます。トップページの作品一覧からも移動できます。

## 自分の旅程を作る

- 初回は空の旅程で始まります。「最初に行きたい場所は？」に都市名・駅・観光スポットなどを入力すると、Google Placesの実際の検索候補を表示します。候補を選ぶと、住所・座標付きで旅程へ追加し、次の場所を検索できます。入力例や履歴からの候補表示はありません。
- Google Maps接続時も「場所名だけで追加する」から自由に入力できます。キー未設定・検索エラー時は手入力のフォームを表示します。手入力だけの場所には座標は付かず、Google Mapsへのリンクで確認できます。
- 「金沢のサンプルを見る」で操作例を試せます。自分で予定を編集するとサンプル表示は外れます。
- 「新しい旅程を作る」で空の旅程に切り替えられます。編集中の旅程や持ち物がある場合は、置き換える前に確認します。「キャンセル」で現在の内容を残せます。
- 旅程・出発時刻・手入力の移動時間・持ち物リストは、このブラウザーのローカルストレージに自動保存します。同じブラウザーで開き直すと続きから編集できます。別の端末やブラウザーとは共有されません。
- 新しい旅程やサンプルへ切り替えると、以前の旅程と持ち物リストを置き換えます。

## 旅程を整える

- 予定の棒を選び、「場所名」を編集して「名前を変更」を押すとリネームできます。滞在時間と手入力の移動時間は維持され、変更した名前も自動保存します。
- 棒の右端をドラッグして滞在時間を15分単位で変更します。右端にフォーカスして矢印キーでも変更できます。
- 棒をドラッグして並べ替えます。選択した予定の「ひとつ前へ」「ひとつ後ろへ」でも操作できます。
- 予定の間の「＋移動」で、移動時間を15分追加します。表示された分数を押すと、5・10・15・30分のボタンや数値入力（0〜240分）で変更できます。Google Maps未接続でも使えます。
- 手入力の移動時間は隣り合う2地点と移動方向に対応します。同じ区間は並べ替えや削除の取り消し後も維持し、新しく隣り合った地点には別途入力します。「入力を解除」でGoogle Mapsの値へ戻せます。
- 予定を外した直後に「元に戻す」で復元できます。

## 旅に合う持ち物

1. 「旅先・場所の情報」と「旅の目的・やりたいこと」を入力します。「旅程の場所を入力する」で登録した場所名を取り込めます。
2. 目的ボタンから、スキー・スノーボード、海・ビーチ、サーフィン、登山・ハイキング、キャンプ、温泉、街歩き、海外旅行を複数選択することもできます。
3. 「持ち物を提案」を押すと、基本の持ち物と、入力キーワード・目的に合う道具のチェックリストを表示します。スキーでは板・ブーツ・リフト券、サーフィンではボード・リーシュコードなどを提案します。共通する道具は重複しません。
4. 準備したものをチェックし、不要なものは外します。自分で必要なものを追加することもできます。

条件を変えて提案し直すと、以前の目的専用の候補は新しい候補に入れ替わります。共通項目のチェックと、自分で追加した持ち物は残ります。外した提案項目は再び候補に入ります。

提案はブラウザー内のキーワードと目的別のリストに基づきます。外部AIや最新の天気・現地情報は取得しません。天候・日数・施設の備品やレンタル条件に合わせて調整してください。旅程と同じく、このブラウザーに条件と準備状況を保存します。

## 紙のしおり・PDF

旅程または持ち物がある状態で「しおり」を押すと、印刷用のプレビューを開きます。旅程の時刻・住所・滞在時間・徒歩移動と、準備済みのチェックを含む持ち物リストを表示します。未入力の移動時間があれば、時刻が目安であることをしおりにも明記します。

旅のあとに「写真を追加」から撮った写真を複数選ぶと、旅程の後ろに「旅のアルバム」を作れます。あとから写真を追加したり、不要な写真だけ外したりできます（JPEG・PNG・WebP、1枚10MBまで）。写真は外部に送信せず、ページの再読み込み・旅程の切り替えまでブラウザー内で保持します。「旅程に戻る」で編集してから再びしおりを開く場合は、写真を保持します。アルバムを残すときはPDFで保存してください。

「印刷・PDF保存」でブラウザーの印刷画面を開きます。A4縦向けのレイアウトで、編集ボタンは印刷しません。写真がある場合は、旅程・持ち物の後ろにアルバムのページを追加します。プリンターまたはPDF保存を選んで出力してください。ページ数は旅程・持ち物・写真の件数に応じて増えます。

## Google Maps

Google CloudでMaps JavaScript API、Routes API、Places API (New) を有効にし、課金設定を済ませます。HTTPリファラーと利用APIを制限したブラウザ用キーを、既存の `.env.local` に追加してください。

```dotenv
VITE_GOOGLE_MAPS_API_KEY=your-browser-api-key
```

開発サーバーを再起動すると、旅程の上にGoogle公式の `PlaceAutocompleteElement` による候補検索を表示します。入力文字列はGoogleへ送信されます。検索候補から選択した後に、場所名・住所・座標だけを取得します。地図の読み込みや経路計算の成否とは独立して検索できます。

本番ではこの環境変数を設定してから再ビルド・デプロイします。キーは公開されるブラウザー用なので、HTTPリファラー制限には本番ドメイン（開発用にはlocalhost）を登録し、API制限にはMaps JavaScript API・Places API (New)・Routes APIを指定してください。キー未設定のままビルドすると、デプロイ後も実際の検索候補は表示されません。Google Maps Platformの利用料金が発生し得るため、課金と予算通知も設定します。

設定後は地図・徒歩経路と移動時間も有効になります。出発から最後の地点までを計算し、帰路は最後に終了地点を追加して表現します。[Google公式の導入手順](https://developers.google.com/maps/documentation/javascript/place-autocomplete-new)を参照してください。

キー未設定時も、予定の編集・名前による追加・移動時間の手入力・Google Mapsへのリンクを使えます。図はサンプル地点の位置関係のみを示します。移動時間を推測で埋めず、未入力の区間があれば明示します。終了時刻には入力・取得済みの区間だけを含めます。地点の変更後も、新しい経路の取得までは古い自動計算の移動時間を使いません。手入力は自動計算より優先し、取得し直しても上書きしません。

```bash
npm test -- src/test/TripPlanner.test.tsx src/test/TripPlannerStart.test.tsx src/test/PlaceSearch.test.tsx src/test/TripMap.test.tsx --maxWorkers=1
npm run build
```
